## 15.1 路线图总览

本路线图覆盖从零到企业级产品的四个Phase，总周期约34-48周（8-12个月）。每个Phase包含完整的功能范围、质量标准、技术里程碑、团队配置和依赖关系。

```
Phase 1: 核心闭环（8-12周）
    需求对话 → 功能地图生成 → 代码生成 → 引导式验收 → 预览URL
    ↓
Phase 2: 质量保障（6-8周）
    三层测试防线 → 安全架构 → 自动部署Production → 多AI模型
    ↓
Phase 3: 规模化（8-12周）
    多项目管理 → 模板库+市场 → PM社区 → 性能优化
    ↓
Phase 4: 企业化（12-16周）
    多人协作 → 私有化部署 → 中国合规 → 企业SSO+审计
```

**关键原则：** 这不是原型或MVP模式。每个Phase交付的都是商业可用的产品增量，有完整的质量保障和可运营的基础设施。

## 15.2 Phase 1: 核心闭环

**目标：** 实现从PM说需求到看到可预览产品的完整链路。单AI模型、单技术栈、纯Web前端，验证"PM驱动AI全自动交付"的核心假设。

**预估周期：** 8-12周
**团队配置：** 3-4人

| 角色 | 人数 | 职责 |
|------|------|------|
| 全栈工程师（偏前端） | 1 | PM GUI层（功能地图+对话面板+验收面板）、ReactFlow集成 |
| 全栈工程师（偏后端） | 1 | DAG引擎、执行引擎、AI Adapter、Pipeline基础 |
| AI/Prompt工程师 | 1 | 需求解析Prompt、代码生成Prompt、业务翻译层 |
| 产品/设计（兼职） | 0.5 | PM视角UX设计、验收流程设计、用户测试 |

### 15.2.1 功能范围（Feature级）

#### F-1.1: 需求对话引擎

**描述：** PM用自然语言描述需求，AI通过结构化追问澄清关键决策点，输出结构化的需求文档。

**功能细节：**
- 自然语言输入框（支持多段描述、粘贴截图说明）
- AI自动追问清单：
  - 业务类型识别（电商/SaaS/内容/工具）
  - 核心用户角色（几种角色、权限差异）
  - 关键业务流程（主流程+异常流程）
  - 数据实体识别（用户、订单、商品等）
  - 第三方集成需求（支付、登录、短信）
  - 视觉风格偏好（现代简约/商务/活泼）
- 追问采用选择题+补充说明模式（永远给PM选择题，不给填空题）
- 追问轮次：3-7轮，平均5轮
- 输出：结构化需求文档（JSON格式，包含功能清单、数据实体、业务规则、集成需求）

**完成定义：**
- [ ] PM输入一段需求描述后，AI在10秒内给出第一个追问
- [ ] 追问覆盖业务类型、用户角色、核心流程、数据实体四个必问维度
- [ ] 每个追问提供2-4个选项+自由补充入口
- [ ] 追问完毕后输出结构化需求文档，PM可确认或修改
- [ ] 支持PM中途说"差不多了"跳过剩余追问

#### F-1.2: 功能地图生成（PM视图DAG）

**描述：** AI根据结构化需求生成PM可理解的功能地图（业务节点DAG），PM确认或修改后进入开发。

**功能细节：**
- 基于ReactFlow的功能地图渲染
- 节点类型使用PM语言（功能/页面/流程/数据/对接/规则/里程碑，对应第13.4节定义）
- 节点标签使用PM需求原文短语（"用户注册"而非"UserRegistration"）
- 业务状态机（待规划→方案中→待确认→开发中→可预览→需修改→已确认→已上线）
- 节点间依赖关系可视化（箭头+关系描述）
- PM可通过对话修改功能地图："把注册和登录分开"、"加一个数据导出功能"
- 每个节点hover显示：功能描述、预估开发时间（AI翻译后的PM语言）、依赖说明
- 自动布局（ELK.js算法）

**完成定义：**
- [ ] AI在60秒内根据需求文档生成功能地图
- [ ] 功能地图节点数在5-20个（中等项目）
- [ ] 所有节点标签为PM可理解的业务语言
- [ ] PM可通过自然语言修改功能地图，AI在15秒内响应
- [ ] 支持拖拽调整节点位置
- [ ] 环检测：添加依赖时实时检测循环并阻止

#### F-1.3: 代码生成引擎（单AI+单技术栈）

**描述：** PM确认功能地图后，AI按拓扑排序逐节点生成代码，全程自动，PM不参与。

**功能细节：**
- 单一AI模型：Claude Sonnet（质量优先）或DeepSeek V3（成本优先），由平台配置决定
- 单一技术栈：Next.js 15 + Supabase（Auth+DB+Storage）+ Tailwind CSS
- 拓扑排序执行：按依赖关系确定生成顺序
- 上下文传递：
  - 直接前驱节点：传递完整输出
  - 间接前驱：传递AI摘要
  - 全局上下文：技术栈声明+编码规范+项目术语表
- 节点状态实时更新（业务状态机）
- 进度流：PM看到业务语言的实时进度（"正在实现用户注册..."、"正在创建商品数据库..."）
- 失败处理：单节点失败自动重试（最多3次），不阻塞无关分支

**完成定义：**
- [ ] 按拓扑序逐节点生成，完成节点实时变色
- [ ] 单节点平均生成时间 < 90秒
- [ ] 单节点失败可自动重试，3次失败后暂停该节点并通知PM
- [ ] 进度流使用PM可理解的业务语言（不出现技术术语）
- [ ] 20节点项目完整生成时间 < 30分钟

#### F-1.4: 质量关卡（后台自动）

**描述：** 代码生成后自动运行Lint+TypeCheck，失败自动修复，PM完全不感知。

**功能细节：**
- ESLint + Prettier 自动格式化和检查
- TypeScript 类型检查（`tsc --noEmit`）
- 失败时AI读取错误信息，自动修改代码，重新检查
- 每个质量关卡最多3次自动修复尝试
- 3次修复失败：暂停Pipeline，在进度流中告知PM"遇到技术问题，正在处理"
- 全部通过后静默进入下一阶段

**完成定义：**
- [ ] Lint检查覆盖所有生成的.ts/.tsx文件
- [ ] TypeCheck覆盖所有生成的TypeScript代码
- [ ] AI自动修复成功率 > 80%（Lint）、> 60%（TypeCheck）
- [ ] PM在正常流程中不会看到任何质量关卡的信息
- [ ] 质量关卡总耗时 < 5分钟（含修复）

#### F-1.5: 预览部署

**描述：** 代码通过质量关卡后，自动构建并部署到预览环境，生成可访问的URL。

**功能细节：**
- `npm run build` 自动构建Next.js项目
- 部署到Cloudflare Pages（Preview环境）
- 自动生成预览URL：`preview-{hash}.projects.ourplatform.com`
- 构建失败时AI分析错误并修复，重新构建（最多3次）
- 部署成功后自动截图（Playwright截取关键页面）
- 冒烟测试：验证首页可访问、关键路由可达

**完成定义：**
- [ ] 构建+部署总耗时 < 3分钟
- [ ] 预览URL可在公网访问
- [ ] 自动截图覆盖所有页面级节点
- [ ] 冒烟测试通过后才进入验收阶段
- [ ] 构建失败AI自动修复成功率 > 70%

#### F-1.6: 引导式验收

**描述：** 系统引导PM逐功能查看截图并回答是/否问题，收集反馈后AI自动修复。

**功能细节：**
- 阶段A：功能清单展示（1分钟）
- 阶段B：逐功能引导（每个功能2-3个是/否问题+截图）
- 阶段C：问题定位（当PM说"否"时，提供选择题定位问题类型）
- 阶段D：验收总结报告
- PM说"不对"时：
  - 结构化引导定位问题（选择题）
  - 支持截图上传标注
  - AI理解后先复述让PM确认，再修复
- 修复循环：修复→重新部署→重新截图→PM再验
- 3轮修不好：自动升级处理方式，建议PM截图标注或标记为"需要技术支持"

**完成定义：**
- [ ] 验收引导支持是/否二选一问题+截图展示
- [ ] PM说"否"时提供4类问题定位选项
- [ ] 支持截图上传（PM标注问题区域）
- [ ] AI修复后自动重新部署并更新截图
- [ ] 验收总结报告展示每个功能的通过/未通过状态
- [ ] 3轮未修复的问题自动升级

#### F-1.7: PM工作台基础UI

**描述：** PM进入产品后的完整界面框架，包含功能地图、对话面板、进度流、验收面板。

**功能细节：**
- 顶部导航栏：项目名称、功能地图/看板切换（Phase 1只做功能地图视图）
- 左侧：对话面板（需求描述+AI追问+修改指令）
- 中央：功能地图（ReactFlow渲染）
- 右侧：进度流（实时业务语言日志）+ 验收面板（Phase 6时切换）
- 面板可拖拽调整大小（react-resizable-panels）
- 响应式设计：支持1280px以上屏幕宽度
- 暗色/亮色主题切换

**完成定义：**
- [ ] 三栏布局可拖拽调整宽度
- [ ] 功能地图在50个节点以下流畅渲染（60fps）
- [ ] 对话面板支持流式输出展示
- [ ] 进度流实时更新，最新消息自动滚动到底部
- [ ] 页面首次加载时间 < 3秒

## 15.3 Phase 2: 质量保障

**目标：** 在Phase 1的核心闭环基础上，建立完整的质量保障体系（三层测试防线+安全架构+自动部署Production），并支持多AI模型。

**预估周期：** 6-8周
**团队配置：** 4-5人（Phase 1团队 + 1人）

| 角色 | 人数 | 职责 |
|------|------|------|
| 全栈工程师（偏前端） | 1 | 验收面板增强、视觉回归对比UI、安全告警翻译 |
| 全栈工程师（偏后端） | 1 | Pipeline Orchestrator完整实现、部署引擎、熔断器 |
| AI/Prompt工程师 | 1 | 交叉验证Prompt设计、多模型Adapter适配 |
| 测试/安全工程师 | 1 | 三层测试防线实现、安全扫描集成、E2E测试框架 |
| 产品/设计（兼职） | 0.5 | 安全告警的PM语言设计、部署流程UX |

### 15.3.1 功能范围

#### F-2.1: 三层测试防线

**描述：** AI全自动生成+运行+修复测试，PM完全不参与，实现88%+的缺陷捕获率。

**功能细节：**

**Layer 1: 同源自测（AI生成测试+执行）**
- AI为每个功能节点自动生成单元测试（Jest/Vitest）
- 测试覆盖率目标 > 60%
- 测试失败时AI分析原因：修代码还是修测试
- 每个测试最多重试3次

**Layer 2: 交叉验证（不同AI独立生成测试）**
- 第二个AI模型从PM需求描述（非代码实现）独立生成测试用例
- 打破"代码和测试同源"的闭环
- 交叉验证发现Layer 1遗漏的逻辑错误
- 每个测试最多重试2次

**Layer 3: 属性测试+变异测试**
- 属性测试（Property-based testing）：验证业务不变量
- 变异测试（Mutation testing）：验证测试本身的质量（能否检测到代码变更）
- 变异存活率 < 30%
- 每个测试最多重试1次

**完成定义：**
- [ ] Layer 1覆盖率 > 60%，自动修复成功率 > 70%
- [ ] Layer 2从需求（非代码）独立生成测试，至少覆盖核心业务流程
- [ ] Layer 3变异存活率 < 30%
- [ ] 三层总缺陷捕获率 > 85%
- [ ] PM在正常流程中完全不感知测试过程
- [ ] 测试总耗时 < 15分钟（20节点项目）

#### F-2.2: 安全架构（Security Layer）

**描述：** 自动化安全扫描集成到Pipeline，中低危自动修复，高危翻译为PM语言告知。

**功能细节：**
- 依赖审计：`npm audit`自动检测已知漏洞
- 静态安全扫描：Semgrep规则集（XSS、SQL注入、路径遍历、敏感信息泄露）
- 代码安全检查：
  - 环境变量不硬编码
  - API Key不写入代码
  - 文件路径Jail Check
  - 第三方库版本无已知CVE
- 安全等级分类：
  - 低危/中危：AI自动修复（如升级依赖版本、替换不安全API）
  - 高危：翻译为PM语言告知（"您的项目有安全隐患需要处理"），附带选择题式修复建议
  - 致命级：阻塞Pipeline，强制处理
- 导出/分享时自动剥离敏感信息（API Key、环境变量）

**完成定义：**
- [ ] npm audit集成到每次构建流程
- [ ] Semgrep至少覆盖OWASP Top 10中与Web应用相关的5类
- [ ] 低危/中危自动修复成功率 > 60%
- [ ] 高危安全问题翻译为PM可理解的语言
- [ ] 导出ZIP时自动剥离所有API Key和.env内容
- [ ] 安全扫描总耗时 < 2分钟

#### F-2.3: 自动部署到Production

**描述：** PM点击"发布"按钮，系统自动完成6项部署检查→Production部署→健康检查→DNS更新。

**功能细节：**
- 三环境自动流转：Preview → Staging（自动测试） → Production（PM点"发布"）
- PM只看到两个概念："预览中"和"已上线"
- 部署前6项自动检查：
  1. 所有测试通过
  2. 安全扫描无高危以上问题
  3. 构建成功
  4. 预览环境冒烟测试通过
  5. PM验收通过
  6. 无未解决的阻塞性问题
- Production部署目标：Cloudflare Pages（前端）+ Railway/Supabase（后端+数据库）
- 部署后健康检查：首页可达+关键API响应正常
- 失败自动回滚+通知PM
- 上线URL：`{project-name}.projects.ourplatform.com`
- 支持PM绑定自定义域名（Phase 2后期）

**完成定义：**
- [ ] PM只需点一个"发布"按钮
- [ ] 6项部署检查全部自动完成
- [ ] Production部署耗时 < 5分钟
- [ ] 部署后健康检查自动执行
- [ ] 部署失败自动回滚并通知PM
- [ ] 上线后URL在公网可访问

#### F-2.4: 多AI模型支持

**描述：** 支持Claude + DeepSeek + 通义千问三家AI Provider，按任务类型智能分配或PM手动选择。

**功能细节：**
- AI Provider Adapter接口统一抽象
- 支持的模型：
  - Claude Sonnet/Haiku（Anthropic API）
  - DeepSeek V3/Coder（DeepSeek API）
  - 通义千问 Max/Plus（阿里云 DashScope API）
- 故障转移：Provider-A超时自动降级到Provider-B
- 连续2个节点连接超时 → 该Provider设circuit breaker
- 按任务类型推荐模型：
  - 架构设计/需求分析 → Claude Sonnet（推理能力强）
  - 代码生成 → DeepSeek Coder（性价比高）
  - 中文需求理解 → 通义千问（中文优化）
- PM可在项目设置中选择默认模型
